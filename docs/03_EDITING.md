# Обновление сайта без CMS

Все редакторские настройки находятся в `source/content.json`. Сохраняйте синтаксис JSON: двойные кавычки, запятые между полями, без комментариев. После изменения выполняйте сборку и проверку из README. Готовые файлы появятся в `dist/`.

| Что менять | Поля |
|---|---|
| Даты | `site.startDate`, `site.endDate`, `site.year`, даты в `program.days`; обновите SEO title / description и тексты FAQ |
| Площадка | `venue.confirmed`, `name`, `address`, `description`, `mapUrl` |
| Билеты | `tickets.status`, `url`, `description`, `options` |
| Программа | `program.status`, `intro`, `days[].sessions` |
| Направления | `directions[]` — стабильные `id`, название, описание, категория |
| Студии | `studios[]` — выводятся только с `confirmed: true` |
| Партнёры | `partners[]` — выводятся только с `confirmed: true` |
| Open Call | `enabled`, текст, `url`, `deadline`, `deadlineConfirmed`, изображение |
| Контакты | `contacts.vk`, `email`, `emailVerified`, `socials`; отдельные ссылки участия и партнёрства тоже замените при необходимости |
| Цвета | `theme` — значения `#RRGGBB` |
| Метрика и верификация | `analytics` |

## Площадка

Сначала внесите название и полный адрес. После утверждения установите `confirmed: true`. До этого сайт показывает «Площадка будет объявлена». После подтверждения адрес появится на странице и в Event JSON-LD. Обновите также соответствующий ответ в `faq`, чтобы все тексты совпадали.

## Билеты

Для запуска заполните утверждённый HTTPS-адрес `tickets.url`, измените `tickets.status` на `on_sale`, отредактируйте описание. До этого посетитель получает только статус ожидания и ссылку на новости в VK.

Пример структуры **после утверждения реальных данных**:

```json
{"name": "Название категории", "price": 1500, "confirmed": true}
```

Поместите такие объекты в `tickets.options`. Число в примере — образец структуры, оно не опубликовано на сайте. Утверждённые цены появятся только при запущенных продажах. Прямая ссылка ведёт во внешнюю билетную систему; покупка и платёжные данные обрабатываются там.

## Программа по дням и залам

`program.days` содержит три даты и пустые массивы `sessions`. Заполняйте только подтверждённые события:

```json
{
  "confirmed": true,
  "time": "12:00",
  "title": "Название утверждённого блока",
  "hall": "Название зала",
  "level": "Уровень / условия участия",
  "directionId": "tango"
}
```

Пример не является расписанием фестиваля. Блоки показываются в порядке массива; располагайте их по времени. Зал и уровень видны у каждого блока. `directionId` должен соответствовать направлению. После публикации программы измените `program.status` на `published`, обновите `intro` и FAQ. В первом релизе это список в карточках дней; большое многочасовое расписание позднее можно развить в фильтры по залам.

## Студии и партнёры

Пример студии:

```json
{"id":"studio-id","name":"Название","description":"Краткое описание","url":"https://example.org/","directionIds":["tango"],"confirmed":true}
```

Пример партнёра:

```json
{"name":"Название","url":"https://example.org/","logo":"assets/partners/logo.webp","confirmed":true}
```

Логотип положите в `static/assets/partners/`; используйте разрешённые владельцем ресурсы. Если не нужен логотип, оставьте пустую строку: отобразится название. `confirmed: false` не публикуется. Массивы изначально пустые.

## Open Call

- Установите `openCall.enabled: false`, чтобы скрыть раздел **и пункты навигации**.
- Дедлайн публикуется только когда задано `deadline: "YYYY-MM-DD"` и `deadlineConfirmed: true`.
- После окончания подтверждённой даты по московскому времени сборка убирает раздел. JS также скрывает его на уже размещённой старой сборке.
- Без JavaScript автоматическое скрытие на старой сборке не выполняется: пересоберите сайт после дедлайна. Для гарантированного снятия без JS можно поручить серверному cron ежедневную сборку; в первом релизе она не требуется.
- Сейчас дата отсутствует. Актуальность набора не утверждена: сайт предлагает обсуждение участия, не обещает действующий срок приёма.

## Почта

`hello@balfest.ru` появляется только после `emailVerified: true`. Включайте после создания ящика и проверки входящего и исходящего письма. Личная почта не используется. Формы и сбор email гостей в первом релизе отсутствуют.

## Аналитика и поисковые кабинеты

- Метрика выключена. Для подключения укажите `analytics.yandexMetrikaId` и `enabled: true`, затем пересоберите. Счётчик запускается только на `balfest.ru` и `www.balfest.ru`; Webvisor выключен. Проверьте подключение в кабинете Метрики после публикации.
- Google Search Console: внесите полученный токен HTML-верификации в `googleSiteVerification` или подтвердите домен DNS TXT-записью. Это верификация, а не Google Analytics.
- Яндекс Вебмастер: `yandexVerification` принимает токен метатега; DNS-верификация также возможна.
- Добавьте `https://balfest.ru/sitemap.xml` в кабинеты.
- После подтверждения площадки проверьте Schema.org Event. Сейчас указан достоверный город без придуманных адреса, часов, цены и исполнителей. Разметка не гарантирует специальный вид сниппета.

## Изображения и оформление

Первый экран — новая версия зимней композиции MVP без встроенного текста. Горизонтальная афиша Open Call показана целиком; существенные сведения и контакт продублированы **отдельным HTML**, без наложения на афишу. На смартфоне афишу можно открыть крупнее.

Изображения в `source/media/` — полноразмерные исходники. Публичные WebP в `static/assets/` имеют варианты ширины, задаваемые `srcset`. При смене изображения сохраняйте имена или обновите HTML-шаблон / `openCall.image`, размеры и alt. Для смены новой visual-концепции меняются изображения, палитра и CSS; структура контента остаётся.

Сайт использует системный шрифт интерфейса и Georgia с резервным serif: внешних шрифтов и зависимостей от Google Fonts нет. Иллюстрации не подтверждают площадку или фактический вид мероприятия.
